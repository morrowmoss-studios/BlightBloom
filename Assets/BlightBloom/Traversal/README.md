# Traversal prototype

Requires the existing Unity 6000.4.5f1, URP 17.4.0, and Input System 1.19.0 packages. No new packages, input asset changes, or Cinemachine dependency.

## Create and open the scene

1. Close any stale Unity session. In Unity Hub open `/Users/zak/Desktop/MorrowMoss Studios/BlightBloom` with 6000.4.5f1. Do not create a project or open a nested directory.
2. Wait for import and compilation to finish. Check Window > General > Console for errors.
3. Choose **BlightBloom > Create Traversal Sandbox**. This uses Unity scene serialization to create `Assets/Scenes/TraversalSandbox.unity` and its metadata. It leaves currently open scenes untouched and refuses to overwrite an existing sandbox. Run this outside Play mode.
4. Double-click the created scene in the Project window to open it by itself. If Unity asks about other unsaved scenes, choose according to your work; this tool does not save SampleScene.
5. Press Play and click the Game view. WASD moves relative to camera yaw; hold Left Shift to sprint. Move the mouse to orbit. Escape releases the cursor; clicking captures it again. Losing application focus releases the cursor. Stopping Play mode restores its previous state.

The scene has a 60m ground surface, directional light, capsule visual with a forward marker, CharacterController, camera, wall, low step, and slope. It is deliberately finite: going off the edge falls under gravity. There is no respawn or jump. Camera obstruction avoidance is not implemented, so the orbit camera can pass through test geometry.

## Inspector configuration

- **Prototype Player / TraversalInput**: existing `InputSystem_Actions` asset. This component clones the asset at runtime and enables only Player/Move, Player/Look, and Player/Sprint; it does not enable combat or UI actions or change the source asset.
- **Prototype Player / ThirdPersonMotor**: input source, movement camera, walk speed (3 m/s), sprint speed (6 m/s), rotation smoothing, downward gravity (25 m/s²), terminal speed, ground-stick speed. CharacterController provides collision, ground contact, slope limit (45°), and step offset (0.3m). Player origin is at the feet; capsule center is (0,1,0), height 2m, radius 0.4m. Do not add a Rigidbody or another player collider.
- **Traversal Camera / ThirdPersonOrbitCamera**: target, input, world-space follow offset, distance, mouse degrees per pixel, gamepad degrees per second, vertical limits, invert Y, follow/orbit smoothing, initial cursor capture. Mouse deltas are not multiplied by deltaTime. Pitch starts at 20° and clamps between -25° and 70° by default.

To assemble manually: create the ground and sun, a player root with the CharacterController settings above, and a collider-free capsule child at local (0,1,0). Add TraversalInput and ThirdPersonMotor to the player and assign the existing actions. Create a separate MainCamera with Camera, AudioListener, URP additional camera data, and ThirdPersonOrbitCamera. Assign the player and input to the camera, and the camera Transform and input to the motor. Save as TraversalSandbox under Assets/Scenes.

## Manual acceptance checks

- Walk forward, backward, sideways, and diagonally. Diagonal speed should match straight movement. Rotate the camera 90° and verify W follows its new horizontal heading.
- Hold/release Left Shift: speed should switch between 3 and 6 m/s. The forward marker should turn smoothly toward travel, including when moving backward relative to the camera.
- Walk into the wall, onto/off the low step and slope, and off the ground edge. Verify blocking, grounded descent, and falling under gravity.
- Sweep mouse vertically to both limits; orbit while walking; test Inspector sensitivity and smoothing values. Compare movement at different frame rates.
- Escape, click to recapture, switch applications, and stop Play mode. Confirm cursor release and no stuck movement when unfocused.
- Check the Console for errors during scene creation and Play mode. Re-run the menu command and verify it refuses to overwrite the scene.

## Validation status

Runtime scripts and Editor builder were compiled with Unity's bundled Roslyn compiler using the project's cached compiler references. This checks C# and referenced APIs, not live Editor import, scene creation, physics, rendering, input, or Play mode behavior. CLI reported no connected Editor during implementation. The scene is intentionally generated by the menu command after import rather than supplied as handwritten YAML. No build settings changes are required for Play mode.
